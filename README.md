# Wine Tasting Lab v0.1

個人用のワイン比較・学習ノート。日本語UI、HTML/CSS/Vanilla JavaScript、外部ライブラリ・API・認証・ビルド不要。アプリ本体は **index.html 1ファイル**です。

## 起動

1. `index.html` をChrome、Safari、Edge、Firefoxなどのブラウザで開きます。
2. 「新しいセッション」→「最初のワインを記録」で始めます。
3. 入力は自動保存。「記録を完了」で集計対象になり、「完了して次へ」で続けて入力できます。

ローカルファイルでの保存の扱いはブラウザに依存します。ファイルを移動・改名する前にJSONバックアップを取得してください。スマートフォンでは、静的ホスティングした同じURLを使うと運用しやすくなります。サーバーはアプリ動作の必須条件ではありません。

## 使い方

- **ホーム**：実記録の本数・品種数・平均好み、最近の記録、前回のノート、好みの傾向。
- **セッション**：日時・場所・目的・メモを保存。セッションごとの一覧・比較・連続入力。
- **クイックノート**：名前（任意）・種類・香り・酸味／甘味／ボディ／タンニン・好み・ひとこと。すべての数値は未入力から開始。
- **詳細モード**：基本情報、外観、香りの強さ・由来、風味・余韻、品質考察、製法・熟成情報。表示を切り替えても内容は消えません。
- **ブラインド**：セッションから開始。予想を入力し「予想を確定して答え合わせ」。予想のスナップショットを保存し、正解は基本情報に手動入力。事前登録済みの正解を講師が配る機能はありません。
- **比較**：2〜4本を選択。SVGレーダー、数値、差分（2本時）、共通／非共通の香り、コメント。未入力と対象外はゼロに置換しません。
- **ライブラリ**：検索・品種・国／地域・種類・セッション・お気に入り・並べ替え。編集・複製・削除。
- **設定**：テーマ、用語ヘルプ、データ入出力、デモ削除。

デモは架空の3件です。デモセッション内に追加したノートもデモ扱いになります。実記録は新しいセッションを作ってください。下書きとデモは本数・好み分析から除外します。ブレンドは入力された組み合わせ単位で好みを集計します。

## 保存の仕組み

`localStorage` の `wine-tasting-lab-v1` に、スキーマv1のJSONとして保存します。

- セッション・ノートのID、作成日時・更新日時を保持。
- テキスト入力、評価、タグ選択の変更ごとに保存。書き込み成功時のみ「保存済み」を表示。
- 編集中の下書きは再読み込み後に開き直します。完了済みノートはホームから再開できます。
- 「未入力」は値なしまたは `null`、タンニンの「対象外」は `na`、評価済みは1〜5。
- ブラインド予想は `prediction`、回答前の確定予想は `predictionSnapshot`、正解は通常の基本情報に保存。
- 別タブの更新を検知した場合は上書きを停止。必要ならJSONに退避してから再読み込みしてください。
- 読み込みに失敗した元データは自動で上書きしません。設定から退避・初期化できます。

端末・ブラウザ・サイトのオリジンごとにデータは独立しています。ブラウザデータの消去、プライベートモードの終了、容量制限などで記録を維持できない場合があります。JSONを定期的に保存してください。履歴は複数のテイスティング記録として保持し、各編集操作の世代履歴までは保存しません。

## JSONバックアップと復元

1. 設定 →「JSONを書き出す」で全データをダウンロード。
2. 復元先で 設定 →「JSONを読み込む」。
3. 形式・ID・参照・評価値・サイズなどの検証後、件数を確認。
4. 「マージ」は同じIDの既存データを優先し、新しいIDだけ追加。同じバックアップの再読み込みでは増殖しません。
5. 「すべて置き換える」は確認後に全データを上書き。先に現在のバックアップを取ってください。

取り込みは15MB以下、ノート20,000件以下、セッション10,000件以下。ただしこれは検証上限であり、ブラウザの実保存容量を保証しません。未対応のスキーマは拒否します。今後のバージョン移行処理は未実装です。JSONには正解・予想・下書きを含みます。ブラインド中でもバックアップ内部の情報を秘匿する暗号化は行いません。

## CSV

設定 →「CSVを書き出す」。UTF-8 BOM付き、1行1テイスティング記録。セッション情報、主要評価、香り、コメント、製法、回答前の予想などを含みます。CSVは分析用で、完全復元にはJSONを使用してください。

カンマ・改行・ダブルクォートをエスケープし、数式として扱われる可能性のある先頭文字にはアポストロフィを付けます。ブラインド未回答の識別情報はCSVでは非表示にします。表計算ソフトで再保存するときは、文字列の扱いを維持してください。

## 静的ホスティング

アプリの公開作業はまだ行っていません。公開するのは `index.html` のみで構いません。個人のバックアップJSONを公開フォルダに含めないでください。

### GitHub Pages

1. リポジトリのルートに `index.html` を置きます。
2. Settings → Pages → Build and deployment で「Deploy from a branch」を選びます。
3. 対象ブランチと `/ (root)` を選択して保存します。
4. デプロイ後、表示されるURLを開きます。

ビルドコマンドは不要です。[GitHub公式：公開元の設定](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)、[サイトの作成](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site)。

### Cloudflare Pages

CloudflareのWorkers & PagesからPagesのDirect Uploadを選び、`index.html` の入ったフォルダまたはZIPをアップロードしてデプロイできます。ソース変更時も再アップロードします。[Cloudflare公式：Direct Upload](https://developers.cloudflare.com/pages/get-started/direct-upload/)。

ローカルファイルから公開URLに切り替える際は、JSONでデータを移します。アプリ自体はデータ表示のための外部通信を行いません。ただしホストされたページの初回読み込みには通信が必要です。Service Workerによるオフライン起動・PWA化はv0.1に含みません。

実機での確認手順：

1. 幅375pxでホーム、ノート、4本比較、設定を開き、横はみ出しを確認。
2. 新規セッションで日本語のノートを入力し、リロード・ブラウザ再起動後の復元を確認。
3. ノートを編集・複製・削除し、未入力と対象外を含む2本を比較。
4. ブラインド予想を入力して再読み込み、確定後に正解を入力して予想保持を確認。
5. JSONのダウンロード／再取り込みとCSVのExcel・Sheetsでの表示を確認。
6. ライト／ダーク、Tab操作、スマートフォンのキーボード表示時の操作を確認。

単一ファイルを優先しているため、クラウド同期・写真添付・AI判定・アカウント・履歴の世代管理はありません。品質評価は個人の考察用で、公式WSET評価や資格判定ではありません。
